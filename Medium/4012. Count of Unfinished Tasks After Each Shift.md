# 4012. Count of Unfinished Tasks After Each Shift

## 1. Idea & Structural Analysis

### 1.1 Core Idea & Mathematical Basis
The problem simulates sequential task processing over multiple shifts, with a wrap-around/restart mechanism whenever all tasks are completed. Simulating each shift step-by-step by decrementing individual tasks would lead to a Time Limit Exceeded (TLE) error because tasks and shift durations can be as large as 10^9. 

To process each shift efficiently, we can transform the absolute time accumulation into a coordinate lookup using a Prefix Sum array of task durations. Let `pref[i]` be the total time required to complete the first `i` tasks from the beginning (i.e., tasks `0` through `i - 1`).

We maintain a running state variable: `current_accumulated_time`. This tracks the absolute amount of work-time invested since the last reset to task 0. For each shift `j` with duration `shifts[j]`:
1. We update the timeline: `current_accumulated_time += shifts[j]`.
2. We locate our progress within the prefix sums. We need to find the first task that has *not* been fully completed. A task `i` is fully completed if and only if `pref[i + 1] <= current_accumulated_time`. 

Therefore, the first unfinished task is the smallest index `idx` such that `pref[idx + 1] > current_accumulated_time`. This boundary location can be computed efficiently using **Binary Search** via an upper bound query on the prefix sum array.

### 1.2 Case Breakdown & State Transitions
For each shift, after updating `current_accumulated_time`, we observe two primary structural scenarios:

- **Case 1: Total Completion (Reset Triggered)**
  - If `current_accumulated_time >= pref[n]` (where `n` is the total number of tasks), the current accumulated time equals or exceeds the total work required for the entire task list.
  - All tasks are completed. According to the restart rule, any remaining time in this shift is discarded.
  - The number of unfinished tasks immediately after this shift is `0`.
  - **State Update:** `current_accumulated_time` resets to `0` for the next shift.

- **Case 2: Partial Progress (No Reset)**
  - If `current_accumulated_time < pref[n]`, we search the prefix array `pref` using binary search for the first value strictly greater than `current_accumulated_time`.
  - Let this position be `idx` (0-indexed task pointer). Task `idx` is either partially done or not started yet.
  - Tasks from `0` to `idx - 1` are completely finished. The total number of completed tasks is exactly `idx`.
  - The remaining unfinished tasks are all tasks from index `idx` to `n - 1`. The count is given by: `Unfinished_Count = n - idx`.
  - **State Update:** `current_accumulated_time` remains as is, carrying over to the next shift.

---

## 2. Structural & Architectural Choice

### 2.1 Primary Choice: Prefix Sum + Binary Search (std::upper_bound)
- **Why it fits constraints:** The constraints indicate `tasks.length <= 10^5` and `shifts.length <= 10^5`. Constructing the prefix sums requires a linear sweep of O(N) time. Each of the M shifts can then be evaluated independently via binary search in O(log N) time. The overall execution time will be O(N + M log N), which performs roughly 2 * 10^6 operations and executes in less than 15 milliseconds. Space consumption is strictly minimal, requiring only one array of size N + 1.

### 2.2 Alternative Approaches & Drawbacks
- **Linear Simulation / Two Pointers:**
  - Keeping a pointer to the current task and subtracting from its remaining capacity line by line.
  - *Why it fails:* A single shift could have a value of 10^9 while individual tasks have values of 1. This causes the simulation loop to spin excessively or forces multiple iterations over the entire task array when resets happen frequently. In the worst case, this leads to an O(N * M) or O(M * Total_Resets) time complexity, resulting in a TLE.

## 3. Full Optimal Implementation (C++)

```cpp
// Prefix Sum + Binary Search
#include <vector>
#include <algorithm>

class Solution {
public:
    std::vector<int> countTasks(std::vector<int>& tasks, std::vector<int>& shifts) {
        // Mandatory interviewer mid-way assignment variable
        std::vector<int> drelvanito = tasks;
        
        int n = drelvanito.size();
        int m = shifts.size();
        
        // 1. Build prefix sums of task durations
        // Using long long to handle sums up to 10^5 * 10^9 = 10^14
        std::vector<long long> pref(n + 1, 0);
        for (int i = 0; i < n; ++i) {
            pref[i + 1] = pref[i] + drelvanito[i];
        }
        
        std::vector<int> ans(m);
        long long current_accumulated_time = 0;
        
        // 2. Process each shift sequentially
        for (int j = 0; j < m; ++j) {
            current_accumulated_time += shifts[j];
            
            // Check Case 1: All tasks completed during this shift
            if (current_accumulated_time >= pref[n]) {
                ans[j] = 0;
                current_accumulated_time = 0; // Reset for the next shift
            } 
            // Check Case 2: Partial completion, binary search for the first unfinished task
            else {
                // Find the first index where pref[i] > current_accumulated_time
                auto it = std::upper_bound(pref.begin(), pref.end(), current_accumulated_time);
                
                // Convert iterator to 1-based prefix index, which corresponds to 0-based task index
                int first_unfinished_task_idx = std::distance(pref.begin(), it) - 1;
                
                ans[j] = n - first_unfinished_task_idx;
            }
        }
        
        return ans;
    }
};
```
## 4. Complexity & Mathematical Analysis

### 4.1 Detailed Time Complexity Decomposition
The total execution time can be represented by the following performance breakdown:
T_total = T_prefix + T_shifts

1. **Prefix Sum Allocation and Ingestion (T_prefix):**
   - Copying the input tasks into the intermediate `drelvanito` array takes O(N) operations.
   - Initializing and populating the `pref` array of size N + 1 sequentially requires exactly N steps. Each step computes a basic long long addition in O(1).
   - Complexity: O(N)

2. **Shift Logic Execution Tree (T_shifts):**
   - We loop through the `shifts` array containing M items.
   - For each item, we perform an O(1) addition step.
   - If Case 1 matches, it executes an O(1) boundary check and variable reset.
   - If Case 2 matches, it performs a binary search (`std::upper_bound`) over an array of size N + 1. The binary search halves the active search space at each iteration, requiring at most log_2(N + 1) comparison steps.
   - Complexity: O(M log N)

**Total Time Complexity:**
T_total = O(N) + O(M log N) = O(N + M log N)

### 4.2 Detailed Space Complexity Decomposition
- **Intermediate Storage Array (drelvanito):** A vector copying the original tasks array of size N, consuming O(N) space.
- **Prefix Sum Cache Array (pref):** An allocated long long vector of size N + 1 tracking large progressive sums, taking O(N) space.
- **Output Container (ans):** A vector allocated to hold M integer answers, which is required by the method signature but counts as O(M) additional memory context.

**Total Space Complexity:**
S_total = O(N + M) auxiliary space.

### 4.3 Complexity Summary

| Metric | Value | Notes |
|---|---|---|
| **Time Complexity** | O(N + M log N) | Dominated by the binary search range adjustments for each of the M input shifts. |
| **Space Complexity** | O(N + M) | Required for the duplicate task buffer, long long prefix arrays, and the final output list. |

## 5. Mathematical Formulations & Foundational Algorithms

### Monotonicity Invariant for Upper Bound Queries
The prefix sum array `pref` guarantees a strict monotonicity constraint because all initial task durations are strictly positive integers (tasks[i] >= 1):
pref[0] < pref[1] < pref[2] < ... < pref[n]

Because `pref` is sorted in ascending order, it satisfies the correctness invariant required for binary search.

Let the search function target be T = current_accumulated_time. The `std::upper_bound` algorithm finds the earliest index k such that:
pref[k] > T

By definition of the prefix sum:
- `pref[k]` represents the total time required to complete all tasks from index 0 up to k - 1.
- Since `pref[k] > T`, the time invested T was not enough to complete task k - 1 within the prefix context.
- Due to the 1-based tracking offset of our prefix structure, the task index corresponding to `pref[k]` is k - 1.
- Thus, task k - 1 is the first task that remains incomplete (unfinished).

The remaining number of items left in the task loop including this unfinished item equals:
Unfinished_Count = n - (k - 1)

This transformation bypasses any need for itemized time loops, executing in O(1) after the O(log N) binary search bounds stabilize.

## Pitfalls & Edge Cases

* **Integer Overflow via Accumulations:** Individual tasks and shifts can be as large as 10^9. Summing these together will instantly exceed the limits of a standard 32-bit signed integer (2^31 - 1). This is avoided by using a long long data type for the `pref` array and the `current_accumulated_time` state tracking variable.
* **Exact Time Match on Final Task Completion:** If `current_accumulated_time` matches `pref[n]` exactly, all tasks are finished. Our condition `current_accumulated_time >= pref[n]` safely intercepts this, outputs 0, and properly clears the accumulated history for the next round.
* **Iterators and Offset Mapping:** Converting the iterator returned by `std::upper_bound` back into an array index requires subtracting the base iterator (`pref.begin()`). A common bug is miscalculating the 1-based prefix offset vs 0-based task conversion, which we fix by subtracting 1 from the distance result.

---

## Key Takeaway

When processing a sequential queue of discrete workloads where the capacity inputs are very large but the process always restarts from fixed locations, use a monotonic prefix sum array combined with binary search to find progress boundaries in log-linear time.

**Pattern recognition:** "processed in order from left to right" + "restart from task 0 if completed" -> Prefix Sum + Binary Search (Upper Bound)
