# 4009. Minimum Possible Maximum Waiting Time

## 1. Idea & Structural Analysis

### 1.1 Core Idea & Mathematical Basis
The problem asks us to simulate a sequential queue of cars refuelled by two independent dispensers. The critical constraint is that car `i` becomes allowed to start refueling exactly when car `i - 1` *starts* refueling. This means the timeline for the next car shifts forward by the waiting time of the current car.

Let's maintain the state of the system when car `i` becomes allowed. Each dispenser `j` (where `j` is 0 or 1) has two parameters:
1. `rem_fuel[j]`: The amount of fuel remaining in dispenser `j`.
2. `busy_time[j]`: The time dispenser `j` will remain occupied, **measured from the moment car `i` becomes allowed**.

Suppose car `i` chooses **dispenser 0**. This is valid only if `rem_fuel[0] >= demand[i]`.
- Car `i` waits for `busy_time[0]` seconds before it can start. Its individual waiting time is `busy_time[0]`.
- Car `i` starts refueling at time `busy_time[0]` relative to its allowance time.
- At this exact moment, car `i + 1` becomes allowed. Thus, the timeline for car `i + 1` shifts by `busy_time[0]`.
- With respect to car `i + 1`'s new timeline:
  - Dispenser 0 will be busy for exactly `demand[i]` seconds.
  - Dispenser 1, which was going to be busy for `busy_time[1]` seconds, has now aged by `busy_time[0]` seconds. Its new busy time becomes `max(0, busy_time[1] - busy_time[0])`.

Similarly, if car `i` chooses **dispenser 1**, the individual waiting time is `busy_time[1]`, dispenser 1's new busy time becomes `demand[i]`, and dispenser 0's new busy time becomes `max(0, busy_time[0] - busy_time[1])`.

### 1.2 State Space Reduction & Representation
The constraints are small: `demand.length <= 50`, `fuel[j] <= 50`, and `demand[i] <= 20`. 
Since a dispenser cannot supply more fuel than its initial capacity, `rem_fuel[j]` ranges from `0` to `50`. Furthermore, a dispenser's `busy_time` cannot exceed the maximum fuel it could possibly contain, so `busy_time[j]` is also bounded by `50`.

We can formulate a Dynamic Programming state:
`dp[i][f0][t0]` = `(max_served, min_max_wait)`
- `i`: Index of the current car (`0` to `N`).
- `f0`: Remaining fuel in dispenser 0 (`0` to `fuel[0]`).
- `t0`: Remaining busy time of dispenser 0 (`0` to `50`).

The remaining fuel in dispenser 1 (`f1`) can be implicitly derived because the total fuel consumed by the first `i` served cars equals the sum of their demands. However, since the process can terminate early, it's safer to either store `f1` or derive it if we track transitions cleanly. Given the small constraints, we can explicitly maintain `f0` and compute `f1` based on the path, or simply store `f0` since `fuel[0] <= 50`. The initial total fuel minus `f0` minus the total fuel consumed gives `f1`. To handle early termination perfectly, we can just run a forward push DP or memoized DFS where `f1` is uniquely determined if we only transition through valid states.

## 2. Structural & Architectural Choice

### 2.1 Primary Choice: Top-Down Dynamic Programming with Memoization
- **Why it fits constraints:** The state space size is bounded by `51 * 51 * 51 = 132,651` states. Each state needs to evaluate at most 2 transitions (assigning to dispenser 0 or dispenser 1). This is extremely fast and avoids computing unreachable states.
- **Optimization Tuple:** Each state will return a pair of values: `[max_cars_served, min_of_max_waiting_time]`. When comparing two options, we prioritize maximizing `max_cars_served`. If they are equal, we minimize `min_of_max_waiting_time`.

### 2.2 Alternative Approaches & Drawbacks
- **Breadth-First Search (BFS) / Dijkstra:**
  - One could treat this as a shortest/longest path on a state graph.
  - *Why it is inferior:* A standard BFS without state deduplication would suffer from exponential branch explosion ($2^{50}$). Using a full priority queue (Dijkstra) adds an $O(\log V)$ factor overhead per transition, which is unnecessary compared to direct grid-based memoization.

## 3. Full Optimal Implementation (C++)

```cpp
// Dynamic Programming + Memoization + State Compression
#include <vector>
#include <algorithm>
#include <cstring>

class Solution {
private:
    // Memoization table: dp[i][f0][t0][t1]
    // Since t1 is also bounded by 50, we include it to completely specify the temporal state.
    // State size: 51 * 51 * 51 * 51 = 6,765,201 elements. Fits comfortably in memory.
    // Storing pairs: first = max_served, second = min_max_wait
    std::pair<int, int> memo[51][51][51][51];
    bool visited[51][51][51][51];
    
    std::vector<int> demands;
    int num_cars;

    std::pair<int, int> solve(int i, int f0, int t0, int t1, int f1) {
        // Base case: all cars served
        if (i == num_cars) {
            return {0, 0};
        }

        if (visited[i][f0][t0][t1]) {
            return memo[i][f0][t0][t1];
        }

        int current_demand = demands[i];
        std::pair<int, int> best_res = {0, 0}; // If no dispenser can serve, 0 more cars are served, max_wait = 0

        // Case 1: Try Dispenser 0
        if (f0 >= current_demand) {
            int next_f0 = f0 - current_demand;
            int next_t0 = current_demand;
            int next_t1 = std::max(0, t1 - t0);
            
            std::pair<int, int> next_res = solve(i + 1, next_f0, next_t0, next_t1, f1);
            
            int total_served = 1 + next_res.first;
            int current_max_wait = std::max(t0, next_res.second);
            
            if (total_served > best_res.first) {
                best_res = {total_served, current_max_wait};
            } else if (total_served == best_res.first) {
                best_res.second = std::min(best_res.second, current_max_wait);
            }
        }

        // Case 2: Try Dispenser 1
        if (f1 >= current_demand) {
            int next_f1 = f1 - current_demand;
            int next_t0 = std::max(0, t0 - t1);
            int next_t1 = current_demand;
            
            std::pair<int, int> next_res = solve(i + 1, f0, next_t0, next_t1, next_f1);
            
            int total_served = 1 + next_res.first;
            int current_max_wait = std::max(t1, next_res.second);
            
            if (total_served > best_res.first) {
                best_res = {total_served, current_max_wait};
            } else if (total_served == best_res.first) {
                best_res.second = std::min(best_res.second, current_max_wait);
            }
        }

        visited[i][f0][t0][t1] = true;
        return memo[i][f0][t0][t1] = best_res;
    }

public:
    int minMaxWaitingTime(std::vector<int>& demand, std::vector<int>& fuel) {
        demands = demand;
        num_cars = demand.size();
        
        std::memset(visited, 0, sizeof(visited));
        
        std::pair<int, int> result = solve(0, fuel[0], 0, 0, fuel[1]);
        
        // If no cars can be served at all, return -1
        if (result.first == 0) {
            return -1;
        }
        
        return result.second;
    }
};
```

## 4. Complexity & Mathematical Analysis

### 4.1 Detailed Time Complexity Decomposition
The overall time complexity is governed by the state space exploration of the DP:
T_total = Total_States * Transitions_Per_State

1. **State Space Complexity:**
   - The state transitions contain four changing variables: i (up to 50), f0 (up to 50), t0 (up to 50), and t1 (up to 50).
   - Total maximum unique states = 51 * 51 * 51 * 51 = 6,765,201 states.
2. **Transitions Per State:**
   - From each state, we check exactly 2 options: choosing dispenser 0 or dispenser 1.
   - Each option computes basic arithmetic operations and max/min evaluations in O(1) time.

**Total Time Complexity:**
T_total = O(N * Fuel_0 * Max_T0 * Max_T1) = O(50^4) = 6.76 * 10^6 operations, which safely executes within 20-30 milliseconds.

### 4.2 Detailed Space Complexity Decomposition
- **Memoization Array (memo):** A 4D array of size 51 * 51 * 51 * 51 tracking pairs of integers. Each pair takes 8 bytes. Total size = 6,765,201 * 8 bytes approx 54 MB.
- **Visited Flag Array (visited):** A 4D boolean array of size 51 * 51 * 51 * 51. Total size = 6,765,201 * 1 byte approx 6.7 MB.
- **Recursion Stack Space:** The call stack goes up to depth N = 50. This takes O(N) space, which is entirely negligible.

**Total Space Complexity:**
S_total = 54 MB + 6.7 MB = 60.7 MB, well below typical competitive programming limits (256 MB or 512 MB).

### 4.3 Complexity Summary

| Metric | Value | Notes |
|---|---|---|
| **Time Complexity** | O(N * F^3) | Where N is the number of cars and F is maximum fuel capacity. Bounded by 6.76 * 10^6 steps. |
| **Space Complexity** | O(N * F^3) | Requires approximately 60 MB of auxiliary storage for state memoization. |

## 5. Mathematical Formulations & Foundational Algorithms

### Timeline Shift and Aging Invariant
Let the current global timeline reference point be the moment car i is allowed to refuel. 
If car i selects dispenser 0, it experiences an immediate waiting overhead equal to:
Wait_i = t0

Car i occupies dispenser 0 from time t0 to t0 + demand[i].
The problem specifies that car i + 1 receives allowance exactly when car i starts refueling. Therefore, the new reference point shifts forward by exactly t0 seconds.

To preserve state semantics for car i + 1, all ongoing durations must be aged by subtracting the time shift t0:
- New busy time of dispenser 0: (t0 + demand[i]) - t0 = demand[i]
- New busy time of dispenser 1: max(0, t1 - t0)

This exact subtraction handles the asynchronous nature of the two parallel resources in O(1) without simulating empty time steps.

## Pitfalls & Edge Cases

* **Zero Cars Served:** If the very first car cannot fit into either dispenser, result.first will be 0. The problem requires returning -1 in this case, which is explicitly handled.
* **Tie-Breaking Multi-Objective Optimization:** We must maximize cars served first, and only minimize max waiting time as a secondary condition. Using a custom tuple comparison or manual if-else updates prevents sub-optimal paths from overwriting the true maximum car assignment.
* **Dispenser Time Saturation:** If a dispenser is free before the next shift (t1 < t0), its remaining duration becomes negative after subtraction. Using max(0, t1 - t0) prevents temporal underflows.

---

## Key Takeaway

When simulating parallel shared resources with asynchronous tasks, capture the state by storing remaining durations relative to the latest event timestamp, updating timelines via simple aging transformations.

**Pattern recognition:** "minimum possible value of the maximum waiting time" + "maximize the number of items served" -> Multi-Objective Top-Down Dynamic Programming + Relative Time State Tracking
