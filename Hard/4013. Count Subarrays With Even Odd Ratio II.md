# 4013. Count Subarrays With Even Odd Ratio II

## 1. Idea & Structural Analysis

### 1.1 Core Idea & Mathematical Basis
The problem requires us to find the number of non-empty subarrays where the ratio of even elements $x$ to odd elements $y$ satisfies the inequality:
x / y <= a / b  (given that y > 0)

Since $y > 0$ and both $a, b \ge 1$, we can clear the denominators by multiplying both sides by $y \cdot b$ without changing the inequality sign:
b * x <= a * y
b * x - a * y <= 0

This transformation allows us to decouple individual elements. If we map each **even** number to a value of $+b$ and each **odd** number to a value of $-a$, the sum of this transformed array over any subarray will be precisely equal to $b \cdot x - a \cdot y$. 

Consequently, a subarray is valid if and only if its sum in the transformed array is less than or equal to $0$.

### 1.2 Handling the $y > 0$ Constraint
What happens if a subarray contains only even elements ($y = 0$)? 
- The transformed sum would be $b \cdot x$. 
- Since $b \ge 1$ and $x > 0$ for a non-empty subarray, $b \cdot x > 0$, which strictly violates our transformed condition $\le 0$.
- Thus, the condition $b \cdot x - a \cdot y \le 0$ **automatically eliminates** subarrays with $y = 0$. We do not need any separate tracking for the presence of odd numbers.

### 1.3 Step-by-Step Derivation & Case Breakdown
Let $P[i]$ be the prefix sum of the transformed array up to index $i-1$, with $P[0] = 0$. The sum of a subarray spanning from index $l$ to $r$ (inclusive) is represented as:
Sum(l, r) = P[r + 1] - P[l]

We want $P[r + 1] - P[l] \le 0$, which rearranges to:
P[r + 1] <= P[l]

This means that for each ending position $i = r + 1$, we need to count how many previous starting positions $l < i$ satisfy the condition $P[l] \ge P[i]$. 

This is a classic inversion-like counting problem that can be handled efficiently:
1. **Case 1: Iterating through the array.** As we maintain a frequency map of seen prefix sums, each new prefix sum $P[i]$ queries how many existing elements in our history are greater than or equal to $P[i]$.
2. **Case 2: Processing via Range Queries.** Because the values of $P[i]$ can scale up to $10^{14}$ (given $N \le 10^5$ and $a, b \le 10^9$), we perform **Coordinate Compression** to map the massive values into a dense range of ranks $[1, M]$ where $M \le N + 1$.
3. **Case 3: Updating and Querying.** We utilize a Fenwick Tree (Binary Indexed Tree) to perform point updates and prefix frequency lookups in $O(\log N)$ time per element.

---

## 2. Structural & Architectural Choice

### 2.1 Primary Choice: Coordinate Compression + Fenwick Tree (BIT)
- **Why it fits constraints:** The constraints state $N \le 10^5$. An $O(N \log N)$ approach is highly optimal and comfortably runs within the time limit. The Fenwick tree provides a minimal memory footprint and excellent cache locality compared to a full Segment Tree, keeping execution fast.

### 2.2 Alternative Approaches & Drawbacks
- **Brute Force / O(N²) Simulation:**
  - Checking every pair of $(l, r)$ and counting evens/odds.
  - *Why it fails:* $N = 10^5$ yields $10^{10}$ operations, causing an immediate Time Limit Exceeded (TLE).
- **Segment Tree without Compression:**
  - Attempting to instantiate a segment tree dynamically over the range $[-10^{14}, 10^{14}]$.
  - *Why it fails:* Dynamic node allocation creates substantial overhead, leading to high memory consumption and execution slowdowns. Compression down to a size of $N + 1$ elements completely bypasses this issue.

## 3. Full Optimal Implementation (C#)

```cpp
// Coordinate Compression + Prefix Sum + Fenwick Tree
using System;
using System.Collections.Generic;

public class Solution {
    public long CountRatioSubarrays(int[] nums, int a, int b) {
        int n = nums.Length;
        long[] pref = new long[n + 1];
        
        // 1. Compute the prefix sums of the transformed values
        for (int i = 0; i < n; i++) {
            long transformedValue = (nums[i] % 2 == 0) ? (long)b : -(long)a;
            pref[i + 1] = pref[i] + transformedValue;
        }

        // 2. Coordinate Compression
        // Collect all unique prefix sum values to map them to a dense rank space
        HashSet<long> uniqueVals = new HashSet<long>(pref);
        long[] sortedVals = new long[uniqueVals.Count];
        uniqueVals.CopyTo(sortedVals);
        Array.Sort(sortedVals);

        // 3. Initialize Fenwick Tree
        int m = sortedVals.Length;
        FenwickTree bit = new FenwickTree(m);
        long validSubarrayCount = 0;

        // 4. Process each prefix sum and count valid pairs
        for (int i = 0; i <= n; i++) {
            int rank = BinarySearch(sortedVals, pref[i]) + 1; // 1-based indexing for BIT
            
            if (i > 0) {
                // Total elements processed so far is exactly 'i'
                // Elements >= pref[i] is equivalent to: i - (elements < pref[i])
                // Elements < pref[i] is given by bit.Query(rank - 1)
                int strictlyLessThan = bit.Query(rank - 1);
                validSubarrayCount += (i - strictlyLessThan);
            }
            
            bit.Update(rank, 1);
        }

        return validSubarrayCount;
    }

    private int BinarySearch(long[] arr, long target) {
        int left = 0, right = arr.Length - 1;
        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (arr[mid] == target) return mid;
            if (arr[mid] < target) left = mid + 1;
            else right = mid - 1;
        }
        return -1;
    }
}

public class FenwickTree {
    private int[] tree;
    private int size;

    public FenwickTree(int size) {
        this.size = size;
        this.tree = new int[size + 1];
    }

    public void Update(int index, int delta) {
        while (index <= size) {
            tree[index] += delta;
            index += index & (-index);
        }
    }

    public int Query(int index) {
        int sum = 0;
        while (index > 0) {
            sum += tree[index];
            index -= index & (-index);
        }
        return sum;
    }
}
```

## 4. Complexity & Mathematical Analysis

### 4.1 Detailed Time Complexity Decomposition
The algorithm executes through three distinct sequential phases:
T_total = T_transform + T_compress + T_traverse

1. **Transform and Prefix Construction (T_transform):**
   - We iterate through the array nums of size N exactly once to populate the pref array. Each step does O(1) mathematical mapping.
   - Complexity: O(N)
2. **Coordinate Compression (T_compress):**
   - Deduplicating up to N + 1 elements takes O(N) time via hash set collection.
   - Sorting the array of unique values takes O(N log N) comparisons in the worst case.
   - Complexity: O(N log N)
3. **Fenwick Tree Traversal & Queries (T_traverse):**
   - We execute N + 1 loops. In each iteration, we run a binary search to retrieve the rank, followed by one Fenwick tree query and one update operation.
   - Binary Search takes O(log N) time.
   - Fenwick tree update and query operations visit at most O(log N) nodes.
   - Complexity: O(N log N)

**Total Time Complexity:**
T_total = O(N) + O(N log N) + O(N log N) = O(N log N)

### 4.2 Detailed Space Complexity Decomposition
- **Prefix Sum Array (pref):** Storing N + 1 structural elements of type long requires O(N) space.
- **Compression Data Structures (uniqueVals, sortedVals):** Contains at most N + 1 unique items, requiring O(N) space.
- **Fenwick Tree (tree):** An internal array tracking counts up to size M (where M <= N + 1), requiring O(N) space.

**Total Space Complexity:**
S_total = O(N) auxiliary space.

### 4.3 Complexity Summary

| Metric | Value | Notes |
|---|---|---|
| **Time Complexity** | O(N log N) | Bounded by the coordinate sorting phase and the log-linear Fenwick tree sweeps. |
| **Space Complexity** | O(N) | Requires linear auxiliary storage allocations for prefix arrays and the BIT. |

## 5. Mathematical Formulations & Foundational Algorithms

### Mathematical Transformation of Ratios
The validation rule requires evaluating rational values:
x / y <= a / b

Since the total counts of even numbers x and odd numbers y are strictly non-negative, and y > 0, we cross-multiply without reversing the inequality:
x * b <= a * y
(x * b) - (y * a) <= 0

Let c[i] represent the transformation of element nums[i]:
c[i] = b, if nums[i] is even
c[i] = -a, if nums[i] is odd

The prefix sum is defined as:
P[k] = sum_{j=0}^{k-1} c[j], where P[0] = 0

The algebraic requirement for a subarray ending at r and starting at l reduces to:
P[r + 1] - P[l] <= 0
P[r + 1] <= P[l]

### Complementary Counting via Fenwick Tree
To find elements satisfying P[l] >= P[i] among all previously processed indices l < i:
Total_Elements_Processed = i
Strictly_Lesser_Elements = bit.Query(rank(P[i]) - 1)
Valid_Elements = Total_Elements_Processed - Strictly_Lesser_Elements

This mathematical reduction avoids range queries up to the upper boundary, replacing it with a basic prefix lookup.

## Pitfalls & Edge Cases

* **Integer Overflow in Prefix Accumulations:** The maximum prefix sum value can reach (10^5) * (10^9) = 10^14, which overflows a standard 32-bit signed integer. This is circumvented by casting values to long before computing the prefix updates.
* **Implicit Zero Odd Element Exclusion:** Subarrays missing odd elements entirely (y = 0) are invalid. Since b >= 1 and x > 0, their resulting transformed calculation yields a positive sum (b * x > 0), naturally causing them to fail the <= 0 check without hardcoded filters.
* **Duplicate Prefix Ranks:** When encountering multiple identical prefix values, we use a strict rank - 1 prefix lookup to include all equivalent values in the total count, ensuring accurate non-strict (<=) evaluation.

## Key Takeaway

Transforming complex fractional conditions into independent integer element mappings allows range properties to be analyzed via sequential prefix sums and inversion-counting structures.

**Pattern recognition:** "ratio of elements in a subarray" -> Element Value Transformation + Prefix Sum + Coordinate Compression + Fenwick Tree
